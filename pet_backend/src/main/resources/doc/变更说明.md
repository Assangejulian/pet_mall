# 与《业务设计.md》的差异说明

> 本文记录数据库实现与原始业务设计文档之间的差异，不改原文。

---

## 变更一览

| 编号 | 涉及 | 原文设计 | 实际实现 | 原因 |
|------|------|---------|---------|------|
| C1 | 用户权限 | sys_role + sys_menu + sys_role_menu + sys_user_role 四张 RBAC 表 | user 表增加 role 字段（VARCHAR(20) DEFAULT "user"），去掉四张 RBAC 表 | 项目初期仅需 user/admin 两种角色，RBAC 过度设计 |
| C2 | 用户密码 | 密码加密存储 | 明文存储（开发阶段） | 上线前接入 BCrypt，当前方便调试 |
| C3 | 视频字段名 | video_url / cover_url | url / cover | 与前端类型定义一致，更简短 |
| C4 | 视频新增字段 | — | 新增 user_id, description, likes, comment_count, duration | 视频模块功能扩展 |
| C5 | 用户表新增字段 | — | 新增 openid, face_id, unionid（微信登录支持） | 小程序接入需求 |
| C6 | 评论表字段修正 | 仅基础字段 | 新增 status, deleted, delete_time, create_by, update_by | 内容审核 + 审计需求 |
| C7 | 订单表地址快照 | TEXT | JSON | 结构化地址数据，便于前端直接展示 |
| C8 | 订单项新增字段 | — | 新增 update_time（可空） | 与 BaseEntity 统一 |
| C9 | sys_message 保留 | — | 库中有表但无 Java 实体 | 暂时保留，后续决定是否清理 |

## 数据库规范对照

| 规范项 | 实现 |
|--------|------|
| 表名小写下划线 | ✅ 全部符合 |
| 表名不用复数 | ✅ purchase_order 而非 orders |
| 禁用保留字 | ✅ 避免使用 order、desc、range 等 |
| DECIMAL 金额 | ✅ price、total_amount 等均为 DECIMAL(10,2) |
| JSON 类型 | ✅ product.images、purchase_order.address_snapshot 使用 JSON |
| 字段尽量 NOT NULL | ✅ 关键字段均已添加 NOT NULL |
| 必含三字段 | ✅ id + create_time + update_time（通过 BaseEntity） |
| 主键 BIGINT | ✅ 雪花算法 |
| 布尔不加 is_ 前缀 | ✅ deleted 而非 is_delete |
| 唯一约束用 UNIQUE INDEX | ✅ 手机号、用户名、订单号等 |

## 状态机

- store.status: 0-待审核 1-营业中 2-已关闭
- purchase_order.order_status: 0(待支付) → 1(已支付) → 2(已发货) → 3(已收货) → 4(已评价)
                                0 → -1(取消)
                                2 → -2(申请退单) → -3(退单通过)
                                2 → -4(管理员退单)
- product.status: 0-下架 1-上架 2-已售出
- video.status: 0-下架 1-上架
